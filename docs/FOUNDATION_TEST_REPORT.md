## 4. Key Fixes Applied

1. **Character Facing & Rotation Fix**:
   - **Root Cause**: KayKit `.glb` characters export facing towards `+Z`. In third-person perspective, moving along `-Z` with raw `atan2(move_dir.x, move_dir.z)` caused the character to face backwards toward the camera on spawn and flip 180° upon movement.
   - **Solution**: Re-oriented the mesh child by 180° (`Transform3D(-1, 0, 0, 0, 1, 0, 0, 0, -1, 0, 0, 0)`) so the default orientation points along `-Z`. Updated heading angle calculation to `atan2(-move_dir.x, -move_dir.z)`, guaranteeing the player mesh strictly faces the movement direction in both forward and backward motion.

2. **Animation Player Discovery**:
   - **Root Cause**: `Knight.glb` contains its `AnimationPlayer` nested inside the `Knight` sub-node (`ModelRoot/Knight/AnimationPlayer`). Hardcoded lookups directly under `ModelRoot` failed.
   - **Solution**: Implemented `_find_animation_player()` in `PlayerController`, which searches hierarchical sub-nodes and binds dynamically to the active animation player.

3. **Autoload & Interaction Integration**:
   - **Root Cause**: Autoload singletons `InteractionManager` and `MissionManager` are initialized in the SceneTree root. Standalone static typing needed decoupling from transient script reload contexts.
   - **Solution**: Standardized `InteractionManager` and `MissionManager` autoloads in `project.godot`, ensuring persistent singleton access across all game scenes and UI layers.
